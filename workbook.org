* How to use this workbook
:PROPERTIES:
:VISIBILITY: children
:END:

This is a set of *tasks*, not a textbook. Each exercise hands you a concrete
thing to accomplish against real data. You will not have been told the flag,
function, or syntax you need — reaching for it (=man=, =--help=, =SPC h f=, a
guess) *is* the exercise. Only after trying should you open the folded /Hint/
and /Solution/ under each task.

Never used Emacs or Vim? Start with track 0. Everything below assumes it.

The bare minimum to read this file right now:
- =j= / =k= move down / up a line. =TAB= on a heading opens or closes it.
- If something looks stuck, press =ESC=, then =C-g= (hold Ctrl, press g).
- =SPC q q= quits Emacs.

Everything folds. The file opens showing only the tracks.
- =TAB= on a track  → reveals its exercises (still folded).
- =TAB= on an exercise → reveals the task, plus a folded /Hint/ and /Solution/.
- =TAB= again on /Solution/ → the answer.

Where you see a source block, run it in place with =SPC c c= (or =C-c C-c=).
It executes right here in the lab, in =/root/corpus=, and prints its output
back into the buffer under =#+RESULTS:=.

Suggested order is top to bottom: each track leans on habits from the last.
Mark progress with =C-c C-t= (cycles =TODO=/=DONE=) on any exercise heading.

The data lives in =/root/corpus= plus =/root/workbook-data=, both prepared for
you when the lab starts (see *Setup*).

* 0. Emacs & Vim fundamentals
:PROPERTIES:
:VISIBILITY: children
:END:

From zero to fluent in the editor this whole workbook lives in. This Emacs
speaks *Vim* (via Evil mode): you get Vim's fast, modal editing on top of
Emacs's Org, Babel, SLIME and help system. By the end of this track you will
move without arrow keys, edit with operators, run code blocks, drive a Lisp
REPL, and find the answer to "what does this key do?" yourself.

How keys are written:
- =C-x= means hold Ctrl and press x. =M-x= means hold Meta (Alt/Option) and
  press x. On a Mac terminal, turn on "Use Option as Meta key" (Terminal.app:
  Settings → Profiles → Keyboard; iTerm2: Left Option key → Esc+). Or press
  =ESC= and then the key: =ESC x= is the same as =M-x=.
- =SPC f f= means press space, then f, then f — one after another, not together.
- =RET= is Enter, =TAB= is Tab, =ESC= is Escape.

Your practice files live in =/root/workbook-data/practice=. Links like
[[file:/root/workbook-data/practice/motions.txt][motions.txt]] open with =C-c C-o= while the cursor is on them.

** TODO E0.1 — Modes, and how to always get out
Vim is /modal/: keys mean different things depending on the mode. Look at the
bottom line of the screen (the /mode line/): =<N>= is Normal, =<I>= Insert,
=<V>= Visual, =<E>= plain Emacs. Get into Insert mode, type your name at the
end of this line, and get back to Normal mode. Then undo it.
You'll meet: =i=, =ESC=, =u=, =C-g=, and the mode indicator.
*** Hint
Normal mode is for moving and commanding; Insert mode is for typing text. =i=
enters Insert, =ESC= always returns to Normal. =u= undoes, =C-r= redoes.
=C-g= is Emacs's universal "cancel": it aborts half-typed commands and prompts.
*** Solution
=A= (append at end of line), type your name, =ESC=, then =u=. When lost: =ESC=,
then =C-g=, and look at the mode line. Nothing in Normal mode inserts text, so
stray keypresses are rarely destructive — and =u= fixes the rest.

** TODO E0.2 — Move without arrow keys
Open [[file:/root/workbook-data/practice/motions.txt][motions.txt]] (=C-c C-o= on the link) and follow its instructions
down to the last line and back to the top, never touching an arrow key.
You'll meet: =h j k l=, =w b e=, =0 ^ $=, =gg G=, ={ }=, =C-d C-u=, counts.
*** Hint
=h j k l= are left, down, up, right. =w=/=b= hop by word, =0=/=$= line start and
end, =gg=/=G= buffer top and bottom, =}= / ={= next/previous blank line.
A number before a motion repeats it: =5j=, =3w=, =12G= (line 12).
*** Solution
Muscle memory, not a single answer. The key idea: every motion is a /noun/ you
will later combine with /verbs/ (E0.4). =zz= / =zt= / =zb= put the cursor line
in the middle / top / bottom of the screen. Back to the workbook: =SPC ,= then
pick =workbook.org=.

** TODO E0.3 — Jump, search, and come back
In motions.txt: jump to the =x= in "box" with one command, find both
=TREASURE= lines, bounce between matching brackets, then return to where you
started.
You'll meet: =f= / =t= / =;=, =/= search with =n= / =N=, =*=, =%=, =C-o=.
*** Hint
=fx= lands on the next =x= in the line; =;= repeats it. =/TREASURE RET=
searches, =n= / =N= step through hits (the counter in the mode line shows
"which of how many"). =%= on a bracket jumps to its partner. =C-o= walks back
through your jump history.
*** Solution
=fx=, then =/TREASURE RET n=, then =%= on the =(=, then =C-o= a few times.
=*= searches for the word under the cursor — the fastest way to find other uses
of a name in code.

** TODO E0.4 — Operators: the grammar of Vim
Open [[file:/root/workbook-data/practice/edit-me.txt][edit-me.txt]] and fix lines 1–12. Each line names the keys to use.
You'll meet: =d= / =c= / =y= + motion, text objects (=iw=, =i"=, =i(=), =dd=,
=p=, =r=, =J=, =.=, =gU=.
*** Hint
Vim edits are sentences: /operator/ + /motion/. =d= deletes, =c= changes
(deletes and enters Insert), =y= yanks (copies). =dw= deletes a word, =d$= to the
end of the line, =ciw= changes the word under the cursor, =ci"= everything
inside the quotes, =ci(= everything inside the parens. Doubling an operator
acts on the whole line: =dd=, =cc=, =yy=. =p= / =P= paste after / before. =.=
repeats your last change.
*** Solution
1 =dw= on the second "the" · 2 =cw fast ESC= · 3 =ci" hello ESC= ·
4 =ci( user ESC= · 5 =D= (same as =d$=) · 6 =gUiw= · 7 =r2= on the 1 ·
8–9 =ddp= on line 8 · 10–11 =J= on line 10 · 12 =yy3p=. Once an edit works,
=.= repeats it anywhere: fix one typo, jump to the next with =n=, press =.=.

** TODO E0.5 — Visual mode and block editing
In edit-me.txt, select lines 13–16 and indent them, then use a /block/
selection to put =- = in front of all four at once.
You'll meet: =v=, =V=, =C-v=, =>=, block insert with =I=.
*** Hint
=v= selects characters, =V= whole lines, =C-v= a rectangle. Any operator works
on a selection: =d=, =y=, =c=, =>= (indent), =<= (dedent), =gU= (uppercase).
In a =C-v= block, =I= inserts on every line once you press =ESC=.
*** Solution
=V3j>= indents. Then put the cursor on the first letter of "apples", =C-v3j=,
=I- ESC=. =gv= reselects the last selection if you need it again.

** TODO E0.6 — Macros: record once, replay many
Undo E0.5 (=u= until it's back), then turn lines 13–16 into =- apples= etc.
with a keyboard macro instead.
You'll meet: =qa= … =q=, =@a=, =@@=, counts on macros.
*** Hint
=qa= starts recording into register =a=; =q= stops. Record the edit for one
line, ending with =j= so the cursor is on the next line. =@a= replays, =3@a=
replays three times.
*** Solution
On "apples": =qa0i- ESCjq=, then =3@a=. Macros are how you do a repetitive edit
awk would be overkill for — track 8 comes back to them.

** TODO E0.7 — Search and replace
In edit-me.txt, replace every =the= with =THE=, confirming each one.
You'll meet: Ex commands (=:=), =:%s=, the =c= flag, =:w=.
*** Hint
=:= opens the Ex command line at the bottom. =:%s/old/new/g= replaces in the
whole file; add =c= (=/gc=) to be asked at each match (=y= / =n=). =:w= saves.
*** Solution
=:%s/the/THE/gc RET=, answer =y= or =n=, then =:w RET= (or =SPC f s=). Emacs
regex syntax differs from grep's for anything fancy — track 8 (E8.3) explores
that. For plain words it just works.

** TODO E0.8 — Files, buffers, and windows
Open employees.csv and sherlock.txt side by side, switch between them, close
one, and get back here.
You'll meet: =SPC .=, =SPC ,=, =SPC f r=, =SPC b k=, =SPC w v= / =SPC w s=,
=C-w= + =h j k l=, =SPC w o=, =SPC w d=.
*** Hint
A /buffer/ is an open thing (file, REPL, help page). A /window/ is a pane
showing a buffer. =SPC .= opens a file (type to narrow, =TAB= to complete a
directory, =RET= to open). =SPC ,= switches buffer. =SPC w v= splits
side-by-side; =C-w l= / =C-w h= moves right/left between windows.
*** Solution
=SPC . /root/corpus/employees.csv RET=, =SPC w v=, =SPC . /root/corpus/sherlock.txt RET=.
Move with =C-w h= / =C-w l=. =SPC b k= kills a buffer, =SPC w d= closes a
window, =SPC w o= keeps only the current one. =SPC f r= reopens recent files.
=SPC o d= brings the dashboard back. Avoid =:q= to close files — in Emacs it
closes the /window/, and on the last one quits Emacs.

** TODO E0.9 — Run any command by name
Without a keybinding, turn on line wrapping in this buffer, then find a command
whose name you only half remember: something with "whitespace".
You'll meet: =SPC SPC= (=M-x=), fuzzy completion, =SPC /= (swiper).
*** Hint
Every Emacs feature is a named command. =SPC SPC= prompts for one; type a few
fragments separated by spaces and the list narrows. =C-n= / =C-p= (or arrows)
move through the list, =RET= runs, =C-g= cancels.
*** Solution
=SPC SPC visual line=, pick =visual-line-mode=, =RET=. =SPC SPC whitespace= shows

** TODO E0.10 — Help yourself (no C-h needed)
Find out: (a) what =SPC c c= runs, (b) what =org-babel-load-languages= is set
to and which file defines it, (c) what the =w= key does in Normal mode.
You'll meet: helpful: =SPC h k=, =SPC h f=, =SPC h v=, =SPC h p=, =SPC h m=, =SPC h b=.
*** Hint
=SPC h k= then press a key sequence: it explains what that key does.
=SPC h f= describes a function, =SPC h v= a variable, =SPC h p= whatever is
under the cursor, =SPC h m= the current modes and their keys, =SPC h b= every
binding (searchable). In a help buffer, =RET= on a link follows it, =q= closes.
*** Solution
(a) =SPC h k SPC c c= → =org-ctrl-c-ctrl-c=. (b) =SPC h v org-babel-load-languages RET=

(c) =SPC h k w= → =evil-forward-word-begin=. This is the most important habit
in the whole workbook: every key, command and variable can tell you about itself.

In [[file:/root/workbook-data/practice/playground.org][playground.org]]: add a third top-level heading with a TODO, give
Groceries a checkbox list, and build a two-column table that aligns itself.

** TODO E0.12 — Babel: code blocks that run
In playground.org, create a bash block that counts the lines of
=/root/corpus/employees.csv=, run it, clear the result, then change it to print
the first 3 lines and run it again.
You'll meet: =<s TAB=, =SPC c c=, =#+RESULTS:=, =SPC c k=, =SPC c e= / =C-c '=,
header args (=:results=, =:dir=, =:var=).
*** Hint
In Insert mode on an empty line, type =<s= then =TAB=: a source block appears.
Type the language (=bash=) after =#+begin_src=. =SPC c c= runs the block under
the cursor, =SPC c k= removes its result. =SPC c e= opens the block in its own

directory, =:var= passes values in. Every block in this workbook is just this.

** TODO E0.13 — One file, many languages

** TODO E0.14 — SLIME: a live Lisp at your fingertips
Open [[file:/root/workbook-data/practice/hello.lisp][hello.lisp]]. Load its definitions into the running Lisp, call =greet=
and =average= from the REPL, then call =broken= and escape the debugger.
You'll meet: =SPC o l= (start SLIME), =SPC l d=, =SPC l k=, =SPC l e=,
=SPC l r=, =SPC l h=, =SPC l .=, the REPL, the debugger.
*** Hint

** TODO E0.15 — Structural editing: slurp, barf, wrap, raise
Work through [[file:/root/workbook-data/practice/parens.lisp][parens.lisp]]: all seven transformations, using only the
structural commands.
You'll meet: paredit via =SPC k s= / =S= / =b= / =B= / =w= / =W= / =r= / =j= / =J=.
*** Hint
Lisp code is a tree of lists; paredit edits the tree, never unbalancing the
parens. /Slurp/ pulls the next thing /into/ the list around the cursor; /barf/
pushes the last thing /out/. Capital letters work on the left side.
=SPC k w= wraps in new parens, =SPC k W= removes the parens around you,
=SPC k r= replaces the parent list with the thing under the cursor,
=SPC k J= / =SPC k j= split and join lists.
*** Solution
1 =SPC k s= · 2 =SPC k b= · 3 =SPC k S= · 4 =SPC k w= then =i print SPC ESC= ·
5 cursor on the =(= of =(compute)=, =SPC k r= · 6 cursor on =progn=, =SPC k W= ·
7 cursor on the space after 2, =SPC k J=; then on the space between the two
lists, =SPC k j=.
In Insert mode, typing =(= always inserts a matching =)=. If a Normal-mode
=x= or =dd= ever leaves parens unbalanced, =u= undoes it; prefer =SPC k W=
for removing parens.

* 1. grep & egrep
:PROPERTIES:
:VISIBILITY: children
:END:

Regex-driven searching. You will discover that the "same" tool has a basic and
an extended dialect, that /where/ a pattern matches matters as much as /what/,
and that grep is only ever a filter — the moment you need to /transform/, you
have outgrown it (that is tracks 2 and 3).

** TODO E1.1 — Is Watson mentioned more than Holmes?
Count, don't eyeball. Get a number for each in =sherlock.txt=.
You'll meet: a counting flag, and case-insensitivity.
*** Hint
There is a flag that prints the count instead of the lines. Names get
capitalised mid-sentence and not — fold case.
*** Solution
#+begin_src bash
grep -ci holmes sherlock.txt
grep -ci watson sherlock.txt
#+end_src

** TODO E1.2 — Lines where BOTH Holmes and Watson appear
One grep matches one pattern. You want the intersection.
You'll meet: grep as a filter you can chain; order-independence.
*** Hint
grep reads stdin. What happens if you pipe one grep into another?
*** Solution
#+begin_src bash
grep Holmes sherlock.txt | grep Watson
#+end_src
Chaining = logical AND. (A single-pass AND needs =awk=, later.)

** TODO E1.3 — Every 404 in the access log — exactly
=grep -c '404' access.log= is wrong. Prove it, then get the true count.
You'll meet: false matches, and why fields beat substrings.
*** Hint
=404= also appears inside byte counts and paths. The status code is the *9th
whitespace field*. grep sees a line, not fields — so anchor the pattern to the
=" 404 = shape, or admit this is really an awk job.
*** Solution
#+begin_src bash
echo "naive:"; grep -c '404' access.log
echo "anchored to the response code:"; grep -cE '" 404 ' access.log
#+end_src
The gap is the lesson: grep matches text, not structure. Track 3 does this right.

** TODO E1.4 — Pull out every IP address
Not the lines containing IPs — the IPs themselves, one per line.
You'll meet: extended regex (=-E=), quantifiers, and =-o=.
*** Hint
=-o= prints only the matched text. A dotted quad is "1–3 digits, a dot, three
times, then 1–3 digits". Repetition =\{1,3\}= is clumsy in basic regex; =-E=
lets you write ={1,3}= and group with =(...)=.
*** Solution
#+begin_src bash
grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' access.log | head
#+end_src

** TODO E1.5 — The 20 longest words in Moby Dick
Words of 12+ letters, ranked by how often they occur.
You'll meet: the =-o= → =sort= → =uniq -c= → =sort -rn= pipeline (memorise it).
*** Hint
=grep -oE '[A-Za-z]{12,}'= gets the words. Downcase them (=tr=) so /Whale/ and
/whale/ merge, then the classic frequency pipeline.
*** Solution
#+begin_src bash
grep -hoE '[A-Za-z]{12,}' moby-dick.txt | tr 'A-Z' 'a-z' \
  | sort | uniq -c | sort -rn | head -20
#+end_src
(=-h= suppresses filenames when you later point this at several files.)

** TODO E1.6 — Which corpus files mention "London"?
The filenames, not the matching lines.
You'll meet: =-l=, =-r=, and =-i= together.
*** Hint
There is a flag that prints only names of files with a match.
*** Solution
#+begin_src bash
grep -rilE 'london' /root/corpus
#+end_src

** TODO E1.7 — Lines with a doubled word ("the the")
Find accidental repeats. Pure grep can do it — barely.
You'll meet: back-references, and =-P= (the moment egrep isn't enough).
*** Hint
Extended regex has no back-reference to a captured group /within the match/.
GNU grep's Perl mode (=-P=) does: =\b(\w+)\s+\1\b=.
*** Solution
#+begin_src bash
printf 'the the game\na a fresh start\nall is well\n' \
  | grep -P '\b(\w+)\s+\1\b'
#+end_src
Hitting grep's ceiling here is exactly why Perl (track 5) exists.

* 2. sed
:PROPERTIES:
:VISIBILITY: children
:END:

The stream editor: line addresses + a tiny command set (=p d s a i c=). You'll
discover it is a scalpel for line-oriented edits and substitution — and that
its power ends where "understand the data as fields/records" begins.

** TODO E2.1 — Print only lines 40–60 of a book
Without opening it in a pager.
You'll meet: =-n=, the =p= command, address ranges.
*** Hint
By default sed prints every line. =-n= silences that; then =p= prints only what
you ask. Addresses can be line numbers: =40,60=.
*** Solution
#+begin_src bash
sed -n '40,60p' moby-dick.txt
#+end_src

** TODO E2.2 — Strip all blank lines from a book
You'll meet: regex addresses, the =d= command.
*** Hint
=/regex/d= deletes matching lines. A blank line is =^$=.
*** Solution
#+begin_src bash
sed '/^$/d' moby-dick.txt | head
#+end_src

** TODO E2.3 — Show only the substitutions you made
Replace "Holmes" with "Poirot", but print *only* the changed lines.
You'll meet: the =s///= command, its =p= flag, and =-n=.
*** Hint
=s/old/new/= substitutes. Add the =p= flag to print lines where it fired, and
=-n= so nothing else prints.
*** Solution
#+begin_src bash
sed -n 's/Holmes/Poirot/gp' sherlock.txt
#+end_src

** TODO E2.4 — Reformat every hire date YYYY-MM-DD → MM/DD/YYYY
In =employees.csv=. The output has slashes.
You'll meet: =-E=, capture groups & back-refs, and picking a new delimiter.
*** Hint
With slashes in the /replacement/, using =s/.../.../= means escaping them all.
sed lets you choose any delimiter: =s#...#...#=. Capture the three date parts
with =( )= under =-E= and reorder with =\1 \2 \3=.
*** Solution

#+begin_src elisp :results silent
(defun corpus-word-freq (file &optional n)
  "Show the top N (default 15) words in FILE."
  (interactive "fCorpus file: ")
  (setq n (or n 15))
  (let ((counts (make-hash-table :test 'equal)))
    (with-temp-buffer
      (insert-file-contents file)
      (downcase-region (point-min) (point-max))
      (goto-char (point-min))
      (while (re-search-forward "[a-z]+" nil t)
        (let ((w (match-string 0)))
          (puthash w (1+ (gethash w counts 0)) counts))))
    (let (pairs)
      (maphash (lambda (k v) (push (cons k v) pairs)) counts)
      (setq pairs (seq-take (sort pairs (lambda (a b) (> (cdr a) (cdr b)))) n))
      (with-current-buffer (get-buffer-create "*freq*")
        (erase-buffer)
        (dolist (p pairs) (insert (format "%6d  %s\n" (cdr p) (car p))))
        (pop-to-buffer (current-buffer))))))

** TODO E10.8 — A macro that writes code for you

* 11. Debuggers
:PROPERTIES:
:VISIBILITY: children
:END:

Stop guessing, start looking. A debugger freezes a running program so you can
walk its call stack, read every variable, and watch the moment a value goes
wrong. You'll use five of them — gdb for C, pdb for Python, Delve for Go, the
Emacs debugger and Edebug for Elisp, and SLIME's debugger for Common Lisp — on
small programs with real bugs, then drive the same sessions from Neovim and
Emacs.

Each language has its own dialect, but the ideas are the same everywhere:
/breakpoint/ (stop here), /step/ (into a call), /next/ (over it), /finish/ or
/out/ (to the caller), /print/ (look), /backtrace/ (how did I get here?), and
/frames/ (move up and down the stack). Learn them once, use them in every
language.

The buggy programs live in =/root/workbook-data/debug=. Each exercise asks you
to find the bug with the debugger, not by reading the source — resist peeking.
Solution blocks run the debugger non-interactively so you can compare notes;
the real exercise is typing those commands yourself.

** TODO E11.1 — gdb: break, run, look
=debug/c/avg.c= averages five scores and prints something absurd. Compile it
for debugging, stop inside =sum=, and find out where the absurd number comes
from.
You'll meet: =gcc -g=, =gdb ./prog=, =break=, =run=, =next=, =print=,
=info args= / =info locals=, =print *ptr@len=.
*** Hint
=-g= adds line and variable information; =-O0= keeps the code close to the
source. In gdb: =break sum=, =run=, then =next= (=n=) line by line and =print=
(=p=) anything. =info locals= shows every local. =p *xs@n= prints /n/ elements
of the array =xs= points to. What is =i= on the last trip round the loop, and
what is =xs[i]= then?
*** Solution
#+begin_src bash :dir /root/workbook-data/debug/c :results output
gcc -g -O0 -Wall avg.c -o avg && ./avg
gdb -q -batch -ex 'break sum' -ex run -ex 'info args' -ex 'print *xs@n' \
    -ex 'print xs[n]' ./avg </dev/null 2>&1 | grep -v -E '^\[|libthread|disabling'
#+end_src
The array holds exactly the five scores, yet the loop runs while =i <= n=, so
it also adds =xs[5]= — whatever garbage sits past the end. Fix: =i < n=.

* Capstone — one question, nine ways

You now have every tool. Answer this with as many of them as you can, then
compare the solutions side by side:

#+begin_quote
"Which five words longer than six letters appear most often across *all* the
prose books, and how many times?"
#+end_quote

** Hint — the shared shape
Lowercase, split on non-letters, keep tokens with =length > 6=, count in a

same five-step shape differently — that's the point.
** Solution — the pipeline version (write the others yourself)

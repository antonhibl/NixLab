* How to use this workbook
:PROPERTIES:
:VISIBILITY: children
:END:

This is a set of *tasks*, not a textbook. Each exercise hands you a concrete
thing to accomplish against real data. You will not have been told the flag,
function, or syntax you need — reaching for it (=man=, =--help=, =SPC h f=, a
guess) *is* the exercise. Work it out in the /Scratch/ block under the task,
and only after trying should you open the folded /Hint/ and /Solution/.

Never used Emacs or Vim? Start with track 0. Everything below assumes it.
New to the command line? Track 2 starts from zero. The tracks run from the
editor and the shell, through the system itself (users, processes, git,
networking, auditing), to programming languages and their debuggers.

The bare minimum to read this file right now:
- =j= / =k= move down / up a line. =TAB= on a heading opens or closes it.
- If something looks stuck, press =ESC=, then =C-g= (hold Ctrl, press g).
- =SPC q q= quits Emacs.

Everything folds. The file opens showing only the tracks.
- =TAB= on a track  → reveals its exercises (still folded).
- =TAB= on an exercise → reveals the task, plus folded /Scratch/, /Hint/ and /Solution/.
- =TAB= on /Scratch/ → an empty source block for your attempt. Type your
  answer between its =#+begin_src= and =#+end_src= lines and run it with =SPC c c=.
  It runs in the same directory as the solution, so the same file names work.
- =TAB= on /Solution/ → the answer, to compare with yours.

Where you see a source block, run it in place with =SPC c c= (or =C-c C-c=).
It executes right here in the lab, in =/root/corpus=, and prints its output
back into the buffer under =#+RESULTS:=.

Suggested order is top to bottom: each track leans on habits from the last.
Mark progress with =C-c C-t= (cycles =TODO=/=DONE=) on any exercise heading.

The data lives in =/root/corpus= plus =/root/workbook-data=, both prepared for
you when the lab starts (see *Setup*).

* 0. Emacs & Vim fundamentals
:PROPERTIES:
:VISIBILITY: children
:END:

From zero to fluent in the editor this whole workbook lives in. This Emacs
speaks *Vim* (via Evil mode): you get Vim's fast, modal editing on top of
Emacs's Org, Babel, SLIME and help system. By the end of this track you will
move without arrow keys, edit with operators, run code blocks, drive a Lisp
REPL, and find the answer to "what does this key do?" yourself.

How keys are written:
- =C-x= means hold Ctrl and press x. =M-x= means hold Meta (Alt/Option) and
  press x. On a Mac terminal, turn on "Use Option as Meta key" (Terminal.app:
  Settings → Profiles → Keyboard; iTerm2: Left Option key → Esc+). Or press
  =ESC= and then the key: =ESC x= is the same as =M-x=.
- =SPC f f= means press space, then f, then f — one after another, not together.
- =RET= is Enter, =TAB= is Tab, =ESC= is Escape.

Your practice files live in =/root/workbook-data/practice=. Links like
[[file:/root/workbook-data/practice/motions.txt][motions.txt]] open with =C-c C-o= while the cursor is on them.

** TODO E0.1 — Modes, and how to always get out
Vim is /modal/: keys mean different things depending on the mode. Look at the
bottom line of the screen (the /mode line/): =<N>= is Normal, =<I>= Insert,
=<V>= Visual, =<E>= plain Emacs. Get into Insert mode, type your name at the
end of this line, and get back to Normal mode. Then undo it.
You'll meet: =i=, =ESC=, =u=, =C-g=, and the mode indicator.
*** Hint
Normal mode is for moving and commanding; Insert mode is for typing text. =i=
enters Insert, =ESC= always returns to Normal. =u= undoes, =C-r= redoes.
=C-g= is Emacs's universal "cancel": it aborts half-typed commands and prompts.
*** Solution
=A= (append at end of line), type your name, =ESC=, then =u=. When lost: =ESC=,
then =C-g=, and look at the mode line. Nothing in Normal mode inserts text, so
stray keypresses are rarely destructive — and =u= fixes the rest.

** TODO E0.2 — Move without arrow keys
Open [[file:/root/workbook-data/practice/motions.txt][motions.txt]] (=C-c C-o= on the link) and follow its instructions
down to the last line and back to the top, never touching an arrow key.
You'll meet: =h j k l=, =w b e=, =0 ^ $=, =gg G=, ={ }=, =C-d C-u=, counts.
*** Hint
=h j k l= are left, down, up, right. =w=/=b= hop by word, =0=/=$= line start and
end, =gg=/=G= buffer top and bottom, =}= / ={= next/previous blank line.
A number before a motion repeats it: =5j=, =3w=, =12G= (line 12).
*** Solution
Muscle memory, not a single answer. The key idea: every motion is a /noun/ you
will later combine with /verbs/ (E0.4). =zz= / =zt= / =zb= put the cursor line
in the middle / top / bottom of the screen. Back to the workbook: =SPC ,= then
pick =workbook.org=.

** TODO E0.3 — Jump, search, and come back
In motions.txt: jump to the =x= in "box" with one command, find both

started.
You'll meet: =f= / =t= / =;=, =/= search with =n= / =N=, =*=, =%=, =C-o=.
*** Hint
=fx= lands on the next =x= in the line; =;= repeats it. =/TREASURE RET=

=*= searches for the word under the cursor — the fastest way to find other uses

** TODO E0.4 — Operators: the grammar of Vim
Open [[file:/root/workbook-data/practice/edit-me.txt][edit-me.txt]] and fix lines 1–12. Each line names the keys to use.
You'll meet: =d= / =c= / =y= + motion, text objects (=iw=, =i"=, =i(=), =dd=,
=p=, =r=, =J=, =.=, =gU=.
*** Hint
Vim edits are sentences: /operator/ + /motion/. =d= deletes, =c= changes
(deletes and enters Insert), =y= yanks (copies). =dw= deletes a word, =d$= to the
end of the line, =ciw= changes the word under the cursor, =ci"= everything
inside the quotes, =ci(= everything inside the parens. Doubling an operator
acts on the whole line: =dd=, =cc=, =yy=. =p= / =P= paste after / before. =.=
repeats your last change.
*** Solution
1 =dw= on the second "the" · 2 =cw fast ESC= · 3 =ci" hello ESC= ·
4 =ci( user ESC= · 5 =D= (same as =d$=) · 6 =gUiw= · 7 =r2= on the 1 ·
8–9 =ddp= on line 8 · 10–11 =J= on line 10 · 12 =yy3p=. Once an edit works,
=.= repeats it anywhere: fix one typo, jump to the next with =n=, press =.=.

** TODO E0.10 — Help yourself (no C-h needed)

** TODO E0.15 — Structural editing: slurp, barf, wrap, raise
Work through [[file:/root/workbook-data/practice/parens.lisp][parens.lisp]]: all seven transformations, using only the
structural commands.
You'll meet: paredit via =SPC k s= / =S= / =b= / =B= / =w= / =W= / =r= / =j= / =J=.
*** Hint
Lisp code is a tree of lists; paredit edits the tree, never unbalancing the
parens. /Slurp/ pulls the next thing /into/ the list around the cursor; /barf/

=SPC k r= replaces the parent list with the thing under the cursor,
=SPC k J= / =SPC k j= split and join lists.
*** Solution

5 cursor on the =(= of =(compute)=, =SPC k r= · 6 cursor on =progn=, =SPC k W= ·
7 cursor on the space after 2, =SPC k J=; then on the space between the two
lists, =SPC k j=.
In Insert mode, typing =(= always inserts a matching =)=. If a Normal-mode
=x= or =dd= ever leaves parens unbalanced, =u= undoes it; prefer =SPC k W=
for removing parens.

* 1. tmux
:PROPERTIES:
:VISIBILITY: children
:END:

A terminal that outlives you. tmux runs /inside/ the lab and keeps your shells,
editors and REPLs alive after you close the terminal: detach, walk away, come
back with =./container-lab.sh enter NAME=, reattach, and everything is exactly
where you left it. It also splits one terminal into windows and panes, so the
editor, a shell, and a =tail -f= can sit side by side for the tracks ahead.

Every tmux command starts with the /prefix/ =C-b= (hold Ctrl, press b, let go),
then a key. So =C-b d= means "Ctrl-b, then d". The lab ships a =~/.tmux.conf=
that adds a few friendlier keys; E1.7 walks through it. From your Mac,
=./container-lab.sh attach NAME= enters a lab straight into a tmux session
called =main=, creating it if needed.

every time.

* 13. Firewalls, routing & traffic control
:PROPERTIES:

Every packet that reaches a Linux machine passes through two kernel systems you
can program from the shell. /netfilter/ decides whether a packet is allowed,
rewritten or logged; it's what =nft= (modern) and =iptables= (classic) talk to.
/Traffic control/ decides how fast and in what order packets leave; =tc= drives
it, and its =netem= module can fake a slow, lossy network on demand.

You need a second machine to point these at, so this track builds one inside
your lab: a separate /network namespace/ called =server=, with its own network

* 16. Auditing with auditd
:PROPERTIES:

who read or changed a file, who ran which program, which access was denied,

Each lab is its own VM with its own kernel, so experimenting here can't affect

(defun corpus-word-freq (file &optional n)
  "Show the top N (default 15) words in FILE."
  (interactive "fCorpus file: ")
  (setq n (or n 15))
  (let ((counts (make-hash-table :test 'equal)))
    (with-temp-buffer
      (insert-file-contents file)
      (downcase-region (point-min) (point-max))
      (goto-char (point-min))
      (while (re-search-forward "[a-z]+" nil t)
        (let ((w (match-string 0)))
          (puthash w (1+ (gethash w counts 0)) counts))))
    (let (pairs)
      (maphash (lambda (k v) (push (cons k v) pairs)) counts)
      (setq pairs (seq-take (sort pairs (lambda (a b) (> (cdr a) (cdr b)))) n))
      (with-current-buffer (get-buffer-create "*freq*")
        (erase-buffer)
        (dolist (p pairs) (insert (format "%6d  %s\n" (cdr p) (car p))))
        (pop-to-buffer (current-buffer))))))

* 24. Debuggers
:PROPERTIES:
:VISIBILITY: children
:END:

Stop guessing, start looking. A debugger freezes a running program so you can
walk its call stack, read every variable, and watch the moment a value goes
wrong. You'll use five of them — gdb for C, pdb for Python, Delve for Go, the
Emacs debugger and Edebug for Elisp, and SLIME's debugger for Common Lisp — on
small programs with real bugs, then drive the same sessions from Neovim and
Emacs.

Each language has its own dialect, but the ideas are the same everywhere:
/breakpoint/ (stop here), /step/ (into a call), /next/ (over it), /finish/ or
/out/ (to the caller), /print/ (look), /backtrace/ (how did I get here?), and
/frames/ (move up and down the stack). Learn them once, use them in every
language.

The buggy programs live in =/root/workbook-data/debug=. Each exercise asks you
to find the bug with the debugger, not by reading the source — resist peeking.
Solution blocks run the debugger non-interactively so you can compare notes;
the real exercise is typing those commands yourself.

*** Scratch

#+end_src

the system's auth logs. =touch= can set a file's /mtime/ and /atime/ to any

** TODO E25.12 — Memory safety: seeing a smashed stack
Down to the lowest level. =/opt/scenario/bin/echoback= copies its argument into

gcc -w -fstack-protector-all -pie -fPIE -Wl,-z,relro,-z,now,-z,noexecstack -D_FORTIFY_SOURCE=2 -O2 echoback.c -o /tmp/echoback_safe

  printf "%-22s " "$b:"
  if command -v readelf >/dev/null; then
    n=$(readelf -lW "$b" | awk "/GNU_STACK/{print (\$0 ~ /RWE/)?\"NX:no\":\"NX:yes\"}")
  else n="NX:n/a"; fi

#+end_src
The hardened build catches the overflow and exits with a guard message
(=buffer overflow detected= from =_FORTIFY_SOURCE=, or =stack smashing detected=
from the canary when you build without =-O2=) instead of jumping to your bytes. =echoback= was built with these protections
/off/ on purpose; real binaries should have them on. When you write C (track 20),
leave the defaults alone — they are these defences.

* 26. Binary exploitation & defense
:PROPERTIES:
:VISIBILITY: children
:END:

The lowest level, where a program is just bytes in memory and a pointer that
says what to run next. Track 25 abused /configuration/; here you abuse /memory/
itself: what happens when a program writes past the end of a buffer, trusts an
index it shouldn't, or returns to an address you chose. These are the bugs
behind a large share of real-world compromises, and the defenses you'll meet —
stack canaries, NX, ASLR, PIE, RELRO, CET — are why modern exploitation is hard.

As in track 25, this teaches /technique/, not turnkey exploits. Every target is
a deliberately-vulnerable practice binary in =/opt/binexp/bin=, every payload

final assembly is always yours to write in /Scratch/; the solutions hand you the
pieces and the method. There is no shellcode and no shell here: the point is to
understand control-flow hijacking and how to prevent it.

You'll drive the binaries with *pwntools*, the standard exploit-development

** TODO E26.3 — Out-of-bounds read: leak a secret
=leak= is built /with/ a stack canary, so a blind overflow dies. But it prints

You'll meet: over-read, =%s= and NUL termination, the canary's null low byte,

*** Scratch
#+begin_src python :results output

#+end_src
*** Hint

** TODO E26.7 — ret2libc and defeating ASLR with a leak

*** Scratch
#+begin_src python :results output

#+end_src
*** Hint

** TODO E26.9 — A managed language can still bite: SBCL and raw memory
Even a garbage-collected Lisp can reach past its safety net through the foreign-
function interface. With SBCL's =sb-alien=, allocate raw C memory, write and read

as E26.3, in a language that usually prevents it. The lesson: the FFI boundary is
where memory-safety guarantees end.
You'll meet: =sb-alien:make-alien=, =deref=, =free-alien=, =sb-sys= system-area

*** Scratch
#+begin_src lisp :results output

#+end_src
*** Hint
=(make-alien (unsigned 8) N)= allocates =N= raw bytes outside the Lisp heap, with
no bounds checking. =(deref ptr i)= reads or writes byte =i=; nothing stops =i=

*** Solution

(let ((v (make-array 8 :element-type '(unsigned-byte 8))))

living inside the editor, Lisp for growing a program interactively, and Nix for

** Hint — the shared shape
Lowercase, split on non-letters, keep tokens with =length > 6=, count in a
map/hash/array, rank descending, take five. Every language above expresses that
same five-step shape differently — that's the point.
** Solution — the pipeline version (write the others yourself)
#+begin_src bash :dir /root/corpus :results output
cat *.txt | grep -oE '[A-Za-z]{7,}' | tr 'A-Z' 'a-z' \
  | sort | uniq -c | sort -rn | head -5
